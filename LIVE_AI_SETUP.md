# Подключение живого ИИ

Сайт остаётся по адресу https://tinyq300.github.io/heritageby/. Для него создан отдельный публичный API на Sites:

https://heritageby-chat-api.ornateball.chatgpt.site

Состояние API: https://heritageby-chat-api.ornateball.chatgpt.site/health

`ready: false` означает, что ключ ещё не добавлен. `ready: true` означает, что ключ задан; доступность самого провайдера проверяется реальным вопросом. Ни один из этих ответов не раскрывает ключ.

## Что нужно сделать владельцу

1. Откройте [страницу ключей OpenRouter](https://openrouter.ai/settings/keys), войдите в аккаунт и нажмите **Create Key**. Назовите ключ, например, `heritageby`.
2. Скопируйте созданный ключ и вставьте его в открытый в Codex локальный файл `.env`, после знака `=`:

   ```dotenv
   OPENROUTER_API_KEY=ваш_ключ
   ```

3. Сохраните файл и напишите в чате **«Ключ добавлен»**. Codex перенесёт значение в секретную серверную переменную `OPENROUTER_API_KEY` сервиса **Heritage Belarus — API исторических бесед**, применит её повторной публикацией и проверит настоящий ответ модели.

Локальный `.env` исключён из Git. Сохранение файла само по себе не обновляет облачный сервер. Ключ не требуется добавлять в GitHub, JavaScript, HTML или настройки посетителя.

Серверная модель по умолчанию — `openrouter/free`: маршрутизатор бесплатных моделей. Он не переключается на платную модель при исчерпании лимита; срабатывает историческая справка. Для бесплатных моделей OpenRouter указывает общий лимит 50 запросов в день для аккаунтов без покупки кредитов. Этот лимит делят посетители сайта. Условия и доступность провайдеров могут меняться. [Официальная информация](https://openrouter.ai/collections/free-models).

## Как работает подключение

Браузер передаёт выбранную героиню, вопрос и последние сообщения в `/api/chat` публичного API. Сервер проверяет тему и длину запроса, сам добавляет исторический контекст и обращается к OpenRouter с секретным ключом. Ответ проверяется; при ошибке или недоступности провайдера возвращается справка. Настоящий ответ отмечается «Ответ ИИ по исторической справке».

На клиенте хранится только адрес API в `js/chat-config.js`. В браузер не передаются ключи и cookies. Сервер разрешает браузерные обращения с `https://tinyq300.github.io`; при смене домена нужно обновить `ALLOWED_ORIGINS`. CORS не является защитой от всех обращений сторонних клиентов. Ограничения частоты на сервере действуют в рамках экземпляра Worker; жёсткий контроль квоты остаётся у провайдера. Для начала используется бесплатная модель.

## Обслуживание

- Локальный сервер: `npm start`, ключ берётся из локального `.env`.
- Общая логика модели: `api/chat-service.cjs`.
- Обработчик облачного API: `api/worker-runtime.mjs`.
- Сборка без зависимостей: `npm run build:api`. Она объединяет те же профили и правила, которые использует галерея.
- Проверки: `npm test`.
- Данные сервиса без секретов: `api/SERVICE.json`.
- После изменения профилей, правил или обработчика необходимо пересобрать и опубликовать API. Обновление GitHub Pages само по себе не меняет Worker.

Публикация API управляется Sites, секрет хранится в production runtime environment. Для повторной публикации используется уже существующий проект из `api/SERVICE.json`; новый сервис создавать не требуется.
